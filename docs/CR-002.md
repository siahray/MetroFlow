## 1. Summary

CR-002 adds **Offline Areas** to the final-product driver app. An Offline Area
bundles the map tiles, road graph, hazard snapshot and active route corridor for
a selected region so a driver can keep navigating when connectivity is lost.

The pilot remains unchanged. CR-001 and the current FSD/TSD deliberately limit
offline support to the cached road graph and keep offline basemap tiles out of
scope. This change request records the final-product extension and the decisions
required before implementation.

## 2. Reason

A driver may enter an area with weak or no mobile data during a flood response.
The cached road graph protects routing, but it does not provide a usable
basemap. Without a downloaded map, the driver loses visual context precisely
when conditions are difficult.

Offline Areas address that gap while keeping a clear boundary between:

- **map availability**, which can be guaranteed after a successful download; and
- **hazard freshness**, which cannot, because the hazard snapshot is only a
  point-in-time copy.

## 3. Change Description

### 3.1 In scope

- Select a region on a coverage map or from an approved region list.
- Download a package containing map tiles, road graph, hazard snapshot, route
  corridor and a signed manifest. The hazard snapshot includes the latest
  verified Sentinel-1 flood extent when available, with acquisition time and
  confidence under proposed [CR-003](CR-003.md).
- Show download progress and support interrupted/resumed downloads.
- Verify package integrity and compatibility before use.
- Show downloaded regions, storage usage and last update time.
- Update or delete a downloaded region.
- Respect a Wi-Fi-only preference and an explicit auto-update preference.
- Show map readiness and hazard freshness as separate states.
- Warn when the hazard snapshot has exceeded its approved age or expiry.
- Display provider attribution and licence notices.

### 3.2 Out of scope

- Changing the pilot delivery or pilot acceptance criteria.
- Live tile streaming while the device is offline.
- Automatic background prefetch without explicit user consent.
- Public App Store or Play Store release, bundle identifiers and signing.
- Native telephony, SOS dispatch or background location.
- Redistribution of provider tiles outside the app.
- A general-purpose map editor or arbitrary user-defined tile packages.
- Replacing the cached-road-graph fallback required by ADR-018; Offline Areas
  supplement it.

## 4. Proposed Architecture

| Area | Proposed change |
| ---- | --------------- |
| Map rendering | Use the ADR-019 MapLibre React Native direction. Keep the local `MapCanvas` only for prototype preview and the no-map fallback. |
| Package source | Choose provider-managed offline packs or self-hosted vector tiles/PMTiles after the licence and cost review in `OD-D23`. |
| Mobile storage | `expo-file-system` for package files and route-corridor assets; `expo-sqlite` for package metadata, versions and checksums. |
| Connectivity | `expo-network` or the approved equivalent to enforce Wi-Fi-only and auto-update preferences. |
| Package contract | Signed manifest with package ID, region bounds, format/version, asset list, compressed size, SHA-256 checksums, graph version, hazard snapshot time, expiry and attribution. When satellite hazards are present, include the source observation ID, Sentinel-1 acquisition time and confidence. Raw scenes and credentials are never packaged. Record as proposed ADR-021. |
| API | Add read-only package discovery and access endpoints; signed URLs must expire and must not expose provider credentials. |
| Security | Verify signature and checksums before use; reject path traversal; keep packages inside the app sandbox; never log signed URLs or credentials. |
| Privacy | Send only the selected region or a coarse area; do not send continuous precise location for package discovery. |
| Data lifecycle | Enforce a storage cap, avoid evicting the active region, retain the last known-good package until an update verifies, and delete all assets on removal. |
| Offline safety | Persist hazard capture time, source and expiry with the package, plus Sentinel-1 acquisition time and confidence for any satellite-derived extent. The UI must state that the snapshot is not live and that extent is not depth or passability. |

The architecture is deliberately not finalised here. The provider, package
format, size cap and update policy are decision `OD-D23` and require academic and
engineering approval.

## 5. Proposed API Surface

| Method | Path | Purpose |
| ------ | ---- | ------- |
| `GET` | `/api/v1/map-packages` | List approved package versions for a coarse region or region ID. |
| `GET` | `/api/v1/map-packages/{package_id}` | Return the manifest, compatibility, expiry, size and attribution. |
| `POST` | `/api/v1/map-packages/{package_id}/access` | Issue short-lived signed asset URLs after authentication and entitlement checks. |

The final shapes must be added to `docs/api.md` before implementation. Asset
delivery may be provider-managed; in that case the access endpoint returns only
the provider offline-region identifier and approved style configuration.

## 7. Risks and Controls

| Risk | Control |
| ---- | ------- |
| A downloaded map is mistaken for live safety data | Separate readiness and freshness states; show capture time and expiry; warn on stale snapshots. |
| Provider licence forbids caching or offline use | Licence review before selecting a provider; record the permitted package model and attribution. |
| A large package exhausts device storage | Approved size cap, pre-download storage check, visible usage and safe eviction rules. |
| Interrupted or corrupt download blocks navigation | Resumable download, checksum/signature verification and retention of the last known-good package. |
| Metered data is consumed unexpectedly | Wi-Fi-only default and explicit auto-update consent. |
| Provider outage prevents package refresh | Last known-good package remains usable until expiry; clearly show its age. |
| Region selection reveals location | Use coarse region IDs or a selected bounding box; do not transmit continuous precise location. |
