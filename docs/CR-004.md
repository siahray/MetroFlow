## 1. Summary

CR-004 defines **where the system's flood state comes from** and what it does when a
source is missing. Live flood state comes from two sources:

1. **PAGASA river telemetry** — river water levels against the Alert, Alarm and
   Critical levels PAGASA publishes for the major river basins.
2. **Satellite flood observations** — Sentinel-1, already approved in CR-003.

**Project NOAH** hazard maps are the **fallback** when no fresh live data covers a
road segment. NOAH maps are modelled flood scenarios (5-, 25- and 100-year return
periods), not observations, so they are applied as a labelled, advisory caution and
never as a closure.

CR-001 already provides the entry point: the sensor gateway accepts a reading and marks
roads inside an impact radius as advisory until a dispatcher confirms them (BRULE-012).
CR-004 adds the sources that feed it and the rule that chooses between sources.

**Revision 1.1 — open sources first.** The Project Lead has directed that the system use
open, free data sources. PAGASA offers no public API, so access depends on a request that
may take time. Revision 1.1 therefore adds open sources that work now, behind the same
adapter interface, so PAGASA can replace or join them later without redesign:

- **Open-Meteo** (open-source, data under CC BY 4.0, no key for non-commercial use): rainfall
  intensity for the rain gate, and **modelled** river discharge from GloFAS through its Flood
  API.
- **NASA GPM IMERG Early Run** (open data, free Earthdata account): satellite rainfall,
  about 4 hours latency at 0.1° and 30-minute steps.
- **Sentinel-1** through Copernicus (open data, free account), as already approved in CR-003.

**Observed versus modelled.** A PAGASA gauge reading is an *observation*. GloFAS river
discharge is a *model output* on a coarse grid, and satellite rainfall is an *estimate*.
Every flood state carries that type, and the apps never present a modelled value as a
measurement.

## 2. Reason

- Routing currently has no real flood data. The only inputs are dispatcher-published
  hazards, driver reports and a manual rainfall simulation.
- A single source is a single point of failure. A gauge can go silent and a satellite
  pass can be days away, so the system needs an ordered fallback.
- A silent feed must not read as "all clear". The system needs an explicit freshness
  rule and a visible source label.

## 3. Change Description

### 3.1 In scope

| Area                | Change                                                                                                   |
| ------------------- | -------------------------------------------------------------------------------------------------------- |
| PAGASA telemetry    | When access is granted: ingest river water-level readings for stations covering the pilot corridor into the existing sensor gateway, with PAGASA Alert/Alarm/Critical levels as thresholds |
| Open data (interim) | Ingest Open-Meteo rainfall and GloFAS modelled river discharge, and NASA GPM IMERG Early rainfall, through the same adapter interface; each value is labelled observed, modelled or estimated |
| Satellite           | Use Sentinel-1 flood observations as defined in CR-003; CR-004 only places them in the priority order   |
| NOAH fallback       | Import NOAH flood hazard maps for the pilot corridor and match them to road segments                    |
| Source priority     | A per-segment rule that picks the best available source by priority and freshness                        |
| Provenance          | Every flood state carries its source, an "as of" time and a freshness state, shown to dispatchers and drivers |
| Manual entry        | Dispatchers can key in a river reading from a PAGASA advisory when no automated feed exists              |
| Sensor visibility   | A portal view of sensors and their latest readings, with a clear *simulated* label for simulated sensors |

### 3.2 Out of scope

| Item                                              | Reason                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------- |
| Scraping PAGASA advisory PDFs                     | Fragile and may breach terms; use a data request or manual entry    |
| Treating NOAH maps as observed or historical floods | They are modelled scenarios                                         |
| Automatic road closure from any non-verified source | Preserves BRULE-012 and BRULE-015                                   |
| Paid data services                                | Academic cost boundary (APPROVALS §1)                               |
| Offline basemap tiles                             | Unchanged (LIM-017)                                                 |

### 3.3 Source priority (default decision)

For each road segment, the first applicable rule wins:

| Priority | Source                                   | Applies when                                                    | Effect on routing                         |
| -------- | ---------------------------------------- | --------------------------------------------------------------- | ----------------------------------------- |
| 1        | Verified hazard (dispatcher published)   | Active                                                          | Per its obstruction level (unchanged)     |
| 2a       | PAGASA river reading (observed)          | Reading is fresh (default window 30 minutes `[TBC]`)            | Advisory until a dispatcher confirms      |
| 2b       | Open modelled river discharge (GloFAS via Open-Meteo) | Value is current and above its alert level `[TBC]`  | Advisory only; labelled *modelled*, never a closure |
| 3        | Satellite observation (CR-003)           | Observation is verified and not expired                         | As verified hazard                        |
| 4        | **NOAH fallback**                        | No fresh priority-2/3 data **and rain is occurring**¹           | Advisory caution and a route cost penalty; **never a closure** |

¹ *Rain is occurring* means rainfall intensity above a configured threshold `[TBC]` from
Open-Meteo or NASA GPM IMERG Early, a rain-gauge reading, or a PAGASA rainfall warning. Without rain, NOAH flood-prone areas are shown on the map
as a static susceptibility layer only. The Project Lead may change this default.

## 5. Proposed Architecture

```
PAGASA access route ─▶ ingestor ─┐
Manual entry (portal) ───────────┼─▶ POST /api/v1/sensors/readings ─▶ threshold + impact radius
Sentinel-1 (CR-003) ─────────────┘                                       │
                                                                          ▼
NOAH shapefiles ─▶ one-off import ─▶ nearest road segments ─▶ flood-state resolver ─▶ routing,
                                                               (priority + freshness)   events, apps
```

- **Ingestors** are small scheduled jobs, one per source. Each registers its stations,
  fetches new readings, converts units (`m` or `mm_hr`) and posts them. A new source
  needs a new adapter only.
- **Flood-state resolver** is a pure function of the latest readings, observations,
  verified hazards, NOAH classes and a rain flag. It is unit-testable without a database.
- **NOAH import** is a one-off job that loads the shapefiles into PostGIS and links
  polygons to road segments. The shapefiles are static data.

## 6. Proposed API Surface

| Method and path                         | Purpose                                                     |
| --------------------------------------- | ----------------------------------------------------------- |
| `POST /api/v1/sensors/readings`         | Existing; also used by ingestors and manual entry           |
| `GET /api/v1/flood-state`               | Resolved state per segment with source, "as of" and freshness |
| `GET /api/v1/noah/layer`                | NOAH polygons for the map layer                             |

## 8. Risks and Controls

| Risk | Control |
| ---- | ------- |
| Open sources are coarse or modelled | Labelled observed / modelled / estimated; advisory only; PAGASA gauges take priority when available (`LIM-027`) |
| Open-source terms and fair use | Keep within Open-Meteo's fair-use guideline (about 10,000 calls per day), attribute CC BY 4.0, confirm terms (`OD-D26`) |
| No public PAGASA API was found | Formal data request; manual entry as the interim source; adapter isolates the access route (`OD-D25`) |
| Stale or wrong external data closes roads | Advisory-only until confirmed (BRULE-016); freshness window; audit of every ingest |
| NOAH fallback over-closes flood-prone roads | Rain gate, caution and route penalty only, never closure |
| Source licence or terms not allowing reuse | Check terms before ingest; record in the TSD |
| Satellite latency mistaken for real time | Show acquisition time; never label a snapshot as live-safe (CR-003) |
| Academic data-privacy approach (A-14) | Public, non-personal data only |
